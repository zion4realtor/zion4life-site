# 有光 (zion4life.faith)

Zion Chen's outreach site, in Chinese and English: 粮仓 (articles, single pages and
videos sorted by tags), 呼吸 (the daily prayer burden), 搭子 (groups that read, pray
and care for new friends together) and 我的. Plain HTML generated by one script with
no dependencies, hosted on Cloudflare (Workers with static assets plus a small Worker
for the groups and the question box), the same setup as zion4realtor.com.

## Words the site uses

The site uses low-key everyday words on purpose. Keep them in titles, menus, URLs and
link previews:

| Meaning | 中文 | English | URL |
| --- | --- | --- | --- |
| Articles and videos | 粮仓 | Granary | `/` (home), `/t/<tag>/`, `/a/<slug>/`, `/v/<slug>/` |
| Prayer, the daily prayer burden | 呼吸 | Breathe | `/huxi/` |
| Groups | 搭子 | Buddies | `/dazi/`, `/g/<id>` |
| Reading the Bible | 吃饭 | Eat | |
| Bible reading group / prayer group / new-believer care | 饭搭子 / 呼吸搭子 / 投喂搭子 | Meal / Breath / Feeding buddies | |
| Life-study group / morning revival group | 细嚼搭子 / 晨兴搭子 | Chew / Morning revival buddies | |

Chinese pages live at the root, English pages under `/en/` with the same path.

## How it works

| What | Where |
| --- | --- |
| Site name, greeting, owner, contact address | `content/site.json` |
| Tags (粮仓 tiles): id, Chinese and English names, color, tile size | `content/tags.json` |
| Articles and single pages: `<slug>.zh.md` and `<slug>.en.md` | `content/articles/` |
| 呼吸, one day each: `YYYY-MM-DD.zh.md` and `YYYY-MM-DD.en.md` | `content/huxi/` |
| Videos (both languages in one entry) | `content/videos.json` |
| Page templates | `build.mjs` |
| Styles, page scripts, fonts, logo, icons | `static/` (`logo.svg` is the logo; WenKai font in `static/fonts/wenkai/`) |
| Accounts (email + 6-digit code, no password), 我的 | `src/auth.js`; page in `static/js/app.js` |
| 留言, 认领 (claims), tag managers' posts (`/x/<id>`), the editor `/write/` | `src/content.js`; pages in `static/js/app.js` |
| 搭子: plaza `/dazi/`, `/dazi/new/`, group `/g/<id>`, session `/g/<id>/<n>` | `src/dazi.js`; pages in `static/js/dazi.js` |
| Zion's page `/admin/` (claims, managers, questions, groups, 留言, posts, accounts) | `src/api.js`; page in `static/js/app.js` |
| The kinds of 搭子 (names, form fields, what each session reads) | `src/kinds.js` |
| Schedules, time zones, calendar files and invitations; Bible books and links | `src/schedule.js`, `src/bible.js` |
| 投喂 lessons (feeding new friends), `01.zh.md`, `01.en.md` … numbered without gaps | `content/feed/` |
| Stored data (accounts, 留言, posts, groups, check-ins, signatures) | `src/store.js` (SQLite-backed Durable Object) |
| Email | `src/mail.js` |
| Shared Markdown | `src/md.js` (used by build.mjs and the Worker) |
| Cloudflare deploy settings | `wrangler.jsonc` |

`node build.mjs` writes the site to `dist/`. The Cloudflare Worker `zion4life` is
connected to this repository: every push to `main` runs `npx wrangler deploy`, which
builds `dist/` and publishes it within a minute or two. Only `/api/*`, `/g/<id>` and
`/x/<id>` (also under `/en/`) run code; build.mjs also writes `/data/*.json` (tags,
pieces, Bible books, 呼吸 days, 投喂 lessons) for the pages and the Worker. Old addresses (`/read/`, `/watch/`, `/pray/`, `/square/`) redirect through
`static/_redirects`.

## Common updates

Zion sends content in one language; Claude translates it into the other. Bible verses
in either language are quoted from the Recovery Version as published (English:
text.recoveryversion.bible or bibleread.online), never from memory.

- **New article or single page:** add `content/articles/<slug>.zh.md` and
  `<slug>.en.md`. Shared fields go in either file's front matter:

  ```
  ---
  title: 人生的奥秘
  summary: 一两句话，显示在卡片上
  date: 2026-10-12
  type: page            # page = 单页; leave out for an article
  tags: mystery, goodnews, life
  ---
  正文……
  ```

  Body is simple Markdown: blank line between paragraphs, `## 小标题`, `- 列表`,
  `**重点**`, `![说明](/img/xxx.jpg)`. A verse is a `>` block whose last line starts
  with `——` for the reference. `sample: true` marks placeholder content (示例 tag,
  not indexed); `hidden: true` keeps a piece off the site. A missing translation
  falls back to the other language with a note.
- **New tag:** add an entry to `content/tags.json` (`tint`: aqua, mint, sky,
  lilac, peach or sun; `size`: `big` or `wide` for larger tiles; `person` for a
  person's tag shows an initial). The home grid always fills whole rows.
- **呼吸:** Zion sends the day's text (a Word file is fine); add
  `content/huxi/<date>.zh.md` and `<date>.en.md` (translated, verses from the Recovery
  Version). Front matter: `date`, `title` (the headline, short) and `lede` (the rest of the
  headline statement). Body: `## 今日祷读经节` with one `>` verse block each (last line
  `—— 弗四16`), `## 今日负担` (the prayers, plain paragraphs), `## 职事的交通` with
  `### headings`; a paragraph that is only `（《书名》第X章　…）` (English: `(*Title*, …)`)
  shows as the source line, `---` separates, and a paragraph only in `*italics*` is a small
  note (not read aloud). Time zones play no part: as soon as a day is pushed, `/huxi/`
  (and the 今日呼吸 tile on the home page) shows it to everyone, wherever they are, and the
  next cron run (within 5 minutes) sends it to the 呼吸 subscribers in 我的 → 消息 (once,
  linked to `/huxi/<date>/`). So a day goes up when Zion sends it, not ahead of time.
- **读给我听:** nothing to do by hand. build.mjs writes `/data/huxi/<date>.speech.json`
  (the day read aloud, references written out, in pieces); after the deploy the cron
  records the latest days with Workers AI (MeloTTS) a few pieces every 5 minutes (a day
  takes about half an hour), kept as 16 kHz μ-law WAV, about 1 MB a minute (`src/wav.js`),
  for 30 days. Until a recording is ready the
  page reads with the phone's own voice. Changing the text records it again.
- **Video:** every video must include the `video` tag, alongside its topic tags; `build.mjs` also adds it automatically. Add an entry to `content/videos.json` with `slug`, `minutes`, `date`,
  `tags`, `zh` and `en` (`title`, `summary`) and `sources`, places to play it from:
  `{ "type": "youtube", "id": "…", "label": "海外线路" }`,
  `{ "type": "bunny", "url": "https://iframe.mediadelivery.net/embed/LIB/ID", "label": "国内线路" }`,
  `{ "type": "iframe", "url": "…" }` or `{ "type": "file", "url": "….mp4" }`. File videos and posters are stored in `static/video/`; keep each file below 25 MiB,
  use fast-start H.264/AAC MP4, and use 44.1 or 48 kHz audio for mobile compatibility.

## Question box (有问题想问？)

Every question is stored and listed on `/admin/`. It is also emailed to Zion when mail
is set up: the `send_email` binding `ASK_MAIL` (Cloudflare Email Routing, destination
Zion's verified address) with `ASK_FROM` (e.g. `light@zion4life.faith`) and `ASK_TO`
variables, or Resend (`RESEND_API_KEY`, `FROM_EMAIL_ADDRESS`, `ASK_TO`).

## Accounts, 留言 and tag managers

- Sign-in: email → a 6-digit code by email (15 minutes, 5 tries) → signed in for a year
  (HttpOnly cookie `yg_s`; only its hash is stored). The first time, a nickname and
  optional identity tags (慕道朋友, 新朋友, 学生, 上班族, 家长, 弟兄, 姊妹, 服事者, 教师),
  hidden from others unless the person shows them. Emails are never sent to any page.
- 留言 on every tag, article, video and post: public, or "only for the managers" (the
  author, the tag's managers and Zion read those). Managers and Zion can remove any.
- Tag managers: Zion appoints anyone to any tag on `/admin/`, or approves a 认领 request
  (the button shows on person tags such as 李光宏). Managers write articles and videos
  into their tags at `/write/`; they appear on the tag page and at `/x/<id>`.
- Zion is the admin: any account whose email is in `ADMIN_EMAILS` (light@zion4life.faith
  and zion.chen@hotmail.com).
- `/admin/` (wide, for a computer): 概况 (counts, countries, identity tags), 注册的人 (a
  table with nickname, full email, country, identity tags, 搭子, subscriptions, 打卡,
  language and time zone, signed up, last seen; search, filters, sort, 导出表格 as a CSV
  that opens in Excel) and 搭子 (kind, status, people, schedule, members), then messages,
  claims, managers, questions, 留言 and posts. The country is Cloudflare's `request.cf.country`,
  stored on sign-in and refreshed with `seen` at most hourly; no IP addresses are stored.

## 搭子 (groups)

- Six kinds, each one entry in `src/kinds.js` (add a kind there; the form, the covenant
  preview and the pages follow): 饭搭子 (Bible chapters, Recovery Version links), 呼吸搭子
  (the day's 呼吸), 投喂搭子 (the 投喂 lessons), 细嚼搭子 (Life-study messages), 晨兴搭子
  (晨兴圣言: weeks of six days, from a chosen week and day, 1/2/3/6 days a time; an
  optional link: a stemofjesse.org day page, or `{w}` and `{d}` for the week and day; without
  one, reminders still say which book, week and day), 粮仓搭子 (one 粮仓 tag's pieces, oldest
  first, including what its managers post). Each group reads in Chinese or English.
- Time zones: the initiator never picks one. The form sends the initiator's phone time zone;
  every page shows times converted to the viewer's own phone (a New York 9:00 is 21:00 in
  Beijing), link previews show no clock times, and emails use the time zone saved on the
  reader's account (updated from their phone when they sign in or open the site).
- The initiator sets the days, time, length and start date, where they meet
  (phone, WeChat, Zoom, WhatsApp, Teams, with details only members see), public (on the
  plaza) or hidden (invite link only), whether plaza visitors may join directly, and the
  size (2–12). Joining is a covenant: read the terms, draw a signature.
- Members open each session's reading at `/g/<id>/<n>`, bookmark paragraphs (or "where I
  stopped"), write notes the group can read, and check in; checking in more than three
  hours after a session ends counts as a make-up (补). The initiator sees a table of
  everyone's check-ins. Each group has a message board.
- The initiator changes the plan in Settings (调整进度): from the next time on (read the
  same chapter again), or what to read when the current plan is done (the next book).
  Each change is a "leg" `{ from, plan }` in `dz.legs`; members get a message.
- 资料: the initiator puts PDFs and pictures in the group (20 MB each, 200 MB a group);
  only members open them. Bytes live in the Durable Object's `blob` table in 1 MB pieces.
- Reminders: the 5-minute cron emails attendees about 30 minutes before each session, with a link to that
  session's reading. Joining emails a calendar invitation (weekly repeat in the group's time
  zone). Each account has a calendar subscription `/api/cal/<key>.ics` covering all their
  groups, and each group offers a downloadable `.ics`.
- Links (in `src/bible.js`): Bible chapters, English
  `bibleread.online/bible/<book>/<chapter>/`, Chinese
  `recoveryversion.com.tw/verse/<book number>/<chapter>?verse=1`; Life-study messages,
  English `bibleread.online/life-study-of-the-bible/life-study-of-<book>/<message>/`, Chinese
  `lsmchinese.org/lifestudy/<code><nn>.html` (an initiator can paste another site; `{n}` in it
  becomes the message number).

## 我的: 消息 and subscriptions

- Signed-in people subscribe to any tag (button on the tag page) and to 呼吸 (button at the
  end of each day). New pieces on the site, posts by a tag's managers and each new 呼吸 day
  become messages in 我的 → 消息; the 我的 tab shows the unread count.
- Groups post there too (plan changes, new files). Zion sends a message to everyone from
  `/admin/` (发消息给所有人).
- Zion's account is light@zion4life.faith, made as the platform's first account when the
  database is empty (`seedAdmin` in `src/store.js`); `ADMIN_EMAILS` lists his admin
  addresses.

## Visit counts (Google Analytics)

`static/js/site.js` loads the Google tag asynchronously for page views so GA4 can derive
approximate city from the connection IP. It disables the tag's automatic page view and sends
one sanitized page view itself; this prevents duplicates with the Worker. Custom actions and
visible time still go through our `/api/hit` to GA4's Measurement Protocol, joined to the
same pseudonymous client ID. If Google is blocked or does not load promptly, the Worker records
page views as a fallback, so visitors in mainland China are still counted. Query strings are
dropped (they hold 搭子 invite codes) except `utm_*` tags. The Worker does not forward IP
addresses; fallback location comes from Cloudflare. `/admin/` is not counted.

- Turn it on: `GA_MEASUREMENT_ID` ("G-…") in `wrangler.jsonc` vars, and the Secret
  `GA_API_SECRET` (GA → Admin → Data streams → the web stream → Measurement Protocol API
  secrets) in the Cloudflare dashboard. Without both, `/api/hit` quietly does nothing.
- Actions: `generate_lead` (有问题想问 sent; mark it as a key event in GA), `sign_up`, `login`,
  `create_group`, `join_group`, `share`, `play_video`, `listen_audio` (读给我听), `time_on_page`.
- Traffic source: utm tags, else the referring site, else the app the link was opened in
  (WeChat, Xiaohongshu, Weibo, QQ send no referrer), sent as `campaign_details`.
- GA's "new users" stays near zero (Measurement Protocol cannot send `first_visit`); use
  total and active users instead.

## Mainland China

- The Google tag loads asynchronously for city-aware page views; if it is blocked or slow, the
  Worker fallback still records traffic. YouTube thumbnails and public CDNs are not loaded on

### Attendance days and later schedule changes

- Joining members may choose a subset of meeting weekdays in their phone’s time zone; the selection can be changed under Settings → My attendance days. Existing members and those selecting every day follow the entire group schedule. Personal reminders, calendar downloads, subscriptions and new invitation attachments respect that selection. The group’s reading progress is shared and is not slowed by individual attendance.
- Initiators can change meeting weekdays, start time and duration from a future effective date under Settings → Change the meeting schedule. Revisions start at the next unstarted session, preserve old session IDs/check-ins/readings and post a group notification. Subscribed calendars update using stable session UIDs and a revision sequence; previously downloaded files must be imported again.
- SQLite migrations add `dz.schedules`, `dz_member.attendance_days` and `dz_member.attendance_tz` without replacing existing rows. A null attendance selection means all days.

### Drip Shepherding image pages and membership

Drip image pages provide a `tag:breathe` subscription and per-article comments shared by the Chinese and English pages. Only registered, signed-in users may post comments, prayers, replies, questions, or suggestions; visitors can read public comments. Both the UI and API enforce this rule.

- Email language defaults to the language last reported by the signed-in device (Chinese → 中文; other device languages → English). Under 我的 → 修改资料, members can select Follow device language, 中文, or English; an explicit language overrides subsequent device changes. Only opted-in attendees receive meeting reminders.

- Session notes are displayed alongside member-only group messages, with a link to the source session. They use the original note row, so existing notes appear automatically and edits/clears stay in sync without duplicate posts. Venue URLs are clickable in both group and session pages.

## Daily Bible reading (2026-10-17)

The homepage links to the stable `/read/today/ot/` URL, with English under `/en/`. The Today page retains its URL while selecting the server publication date at midnight Asia/Shanghai (UTC+8), identically for all visitors. It refreshes its date when reopened or resumed; dated `/read/YYYY-MM-DD/ot/` and `/nt/` pages remain fixed. February 29 repeats February 28 in the 365-day source plan. Past dates and metadata remain in the Eat and Life calendars.

Reading pages have a distinct `read/app.webmanifest` with the stable Today start URL and home-screen instructions. Adding an old dated page should be done through its Today link. The installed shortcut can request playback, but browser autoplay restrictions still apply. It is not an offline Bible app.

The existing five-minute server cron prepares daily source ranges and brief key selections ahead of time. It stores metadata in `reading:day:` blobs without caching complete chapters. Source failures are retried and missing dates show a pending message. Seed metadata and pages for October 17–19 are retained.

Chinese audio references the source recording and credits 台湾福音书房. English full narration uses WEB with Aura 2 Helena; displayed key quotations remain Recovery Version, with separate Recovery Version and WEB source links. Its note states that the site has not obtained LSM permission to publish full Recovery Version narration. No © Living Stream Ministry footer is displayed. Previous short-verse recordings are retained but are not presented as full readings.

Existing recording files and date entries are not deleted. The separate `reading:audio:` prefix is not subject to the prayer recording's 30-day cleanup. The short-verse MP3 endpoint remains available for existing saved links and supports byte ranges.

### World English Bible full narration

From this release, English full narration uses the public-domain World English Bible, updated American-English 66-book edition at https://ebible.org/engwebp/. Recovery Version remains the source of the short displayed key verses. No Recovery Version chapters enter the full-reading TTS input. The page identifies the two sources without a copyright footer for LSM.

`src/reading-web.js` verifies every verse in the original daily ranges, excludes navigation, footnotes and cross references, saves the complete public-domain transcript, splits it at sentence/word boundaries into requests of at most 1,800 characters, and records them using the established Aura 2 Helena voice. The existing five-minute server cron makes up to eight recording requests per run, resumes partial jobs, and only marks an entire reading ready after all chunks are recorded and merged. Per-chunk ID3/Xing headers are removed so native audio players use the whole recording rather than the first segment's duration.

Long-lived storage uses `reading:web:transcript:<date>:<testament>:v1`, `reading:web:job:<hash>`, `reading:web:part:<hash>:<index>` and `reading:web:audio:<hash>`; no automatic pruning applies. The hash is based on the WEB text and voice, allowing identical annual readings to reuse the saved recording. Previous short-verse audio remains untouched. The normal dated MP3 URL serves the full recording once ready, with byte-range support. Coverage can be checked with `/api/reading/YYYY-MM-DD/transcript/ot.json` or `/nt.json` (public-domain text only).

Today's and the next two dates' verified WEB transcripts are seeded in `static/data/reading-web/`. The stable Today links, Beijing-midnight publication, home-screen entry and history calendars are retained. A preparing message is shown until the complete recording is ready; partial recordings are never presented as complete.

Reading is an independent workflow maintained in its dedicated reading chat. Its bilingual layout, source materials, full WEB narration, Recovery Version key quotations, attribution and home-screen instructions follow the reading decisions in that chat. Do not inherit prayer layout, statements, publication dates or audio maintenance policies. `READING_HOME_SCREEN`, `static/js/reading.js`, `static/css/reading.css` and `src/reading*.js` own this behavior. `/api/reading/today.json` is the no-cache server clock; Beijing midnight is noon Eastern daylight time or 11 a.m. Eastern standard time. The five-minute preparation cron runs ahead of publication; prepared future dates are hidden from the calendar until publication.

### Chinese reading recording storage
Chinese reading audio must be served from `/api/reading/<date>/audio/zh/<ot|nt>.mp3`, never from a third-party URL in the browser. The reading preparation cron copies original MP3s into permanent `reading:zh:audio:<source-hash>` blobs and date-specific `reading:zh:manifest:` entries ahead of time. Older dates are also copied on first playback. Validated files are fully stored before serving, support GET/HEAD and byte ranges, and are independent of prayer recording cleanup. Original source metadata remains available to the server for retrieval; failed copies retry and never redirect the visitor to Dropbox.

Video share identity: each `/v/<slug>/` document contains only that film. Horizontal gestures, arrows and completion navigate to another document; do not embed the full library or rewrite history to impersonate another video. Video URLs resolve to a per-slug `share=v3-<slug>` query before rendering, and metadata remains fixed for the document.
